# 第 4 层：Kubernetes

业务进 K8s；Milvus/Redis 仍用 Compose（脚本会自动处理）。

## 本机：你只跑这一条

在项目根目录：

```powershell
powershell -File k8s/ops.ps1 -Action up
```

脚本会自动：

1. 启动 Milvus/Redis 等依赖  
2. 停掉 Compose 里的 ollama/doc-parser/rag-api（避免冲突）  
3. 构建并导入镜像到 K8s（不走外网重下大模型）  
4. 把已有模型拷进集群  
5. 部署并打开端口转发  

完成后打开：**http://localhost:30081**

| 地址 | 用途 |
|------|------|
| http://localhost:30081 | 网页（导入/问答） |
| http://localhost:30099/health | 解析服务 |
| http://localhost:31134/api/tags | 模型列表 |

## 以后改代码

```powershell
powershell -File k8s/ops.ps1 -Action redeploy
```

网页打不开时：

```powershell
powershell -File k8s/ops.ps1 -Action forward
```

## 退回第 3 层 Compose

```powershell
powershell -File k8s/ops.ps1 -Action down
docker compose up -d
```

## 服务器 K8s（了解即可）

1. `docker compose build` 出 `rag-api`、`rag-doc-parser`  
2. 镜像进集群（save/load 或私有仓库）  
3. 改 yaml 里 `host.docker.internal` 为服务器真实 IP  
4. `kubectl apply -f k8s/`
